Multi-Site A/B Testing Analysis

A Bayesian hierarchical model to predict which components truly work across multiple websites, accounting for site-specific effects.

The Challenge

Why standard A/B testing fails when testing the same components across multiple sites

The Problem with Single-Site Testing

When you test Component #1 (Payment Plans) on mindvalley.com and see +20% lift, you don't know if:

  • The component genuinely works everywhere
  • It only works for Mindvalley's specific audience
  • The +20% was statistical noise (false positive)
  • Your traffic source that week was unusually qualified

The Multi-Site Solution

By testing the same 8 components across multiple websites, we can:

  • Separate "true component effect" from "site-specific effect"
  • Identify which components universally work
  • Understand which sites respond best to which tactics
  • Make predictions for NEW sites we haven't tested yet

The Hierarchical Bayesian Model

A rigorous statistical framework for multi-site component testing

Core Model Structure

We model the conversion rate lift for each component on each site as:

yij = μj + αi + βij + εij
Where: yij = observed lift for component j on site i

μj — True Component Effect

The "real" underlying effectiveness of component j, independent of which site it's tested on. This is what we want to learn.

αi — Site-Specific Intercept

Some sites convert better overall. This captures baseline differences (e.g., mindvalley.com converts 3% while testsite.com converts 1.5%).

βij — Interaction Effect

Sometimes a component works great on one site but poorly on another. This captures component × site interactions.

εij — Random Error

Statistical noise from sampling, timing, and unmeasured factors. We assume ε ~ N(0, σ²).

Why "Hierarchical" and "Bayesian"?

Hierarchical (Multi-Level)

Data is structured in levels: observations within components within sites. The model "shares strength" — results from Site A inform estimates for Site B, especially when Site B has limited data.

μj ~ N(μoverall, τ²)
Component effects drawn from a population distribution

Bayesian

We incorporate prior knowledge (e.g., "payment plans typically lift 10-30%") and update beliefs as data arrives. This prevents overfitting to small samples and gives probability distributions, not just point estimates.

P(μ|data) ∝ P(data|μ) × P(μ)
Posterior = Likelihood × Prior

The Algorithm: Step by Step

How we process multi-site A/B test data to identify winning components

1

Data Collection & Structuring

For each component j tested on each site i, collect: visitors (n), conversions (c), baseline conversion rate, and test duration. Structure as a matrix where rows = sites, columns = components.

2

Calculate Observed Lift with Confidence Intervals

For each cell, compute: Lift = (Treatment CR - Control CR) / Control CR. Use Wilson score intervals to get 95% confidence bounds. Flag tests where CI includes 0 (inconclusive).

3

Fit Hierarchical Model via MCMC

Use Markov Chain Monte Carlo (MCMC) to sample from the posterior distribution of μj values. We run 4 chains × 2000 iterations, discarding first 1000 as warmup. Check convergence via R-hat < 1.01.

4

Extract Component Rankings

For each component, compute: (a) Posterior mean of μj = expected lift, (b) P(μj > 0) = probability component is positive, (c) 90% credible interval bounds. Rank by P(μj > 0) × E[μj].

5

Identify Site-Component Interactions

Components with high variance in βij are "site-dependent" — they work well on some sites but not others. Low variance means the component effect is consistent everywhere.

6

Generate Predictions for New Sites

For a new site k not in training data, we can predict expected lift: ŷkj = μj + α̂k where α̂k is estimated from site k's baseline metrics using regression on site features.

# Multi-Site A/B Testing Hierarchical Bayesian Model
# Requires: pip install pymc arviz pandas numpy

import pymc as pm
import numpy as np
import pandas as pd
import arviz as az

def build_hierarchical_model(data):
    """
    Build hierarchical Bayesian model for multi-site A/B testing.

    Parameters:
    -----------
    data : pd.DataFrame
        Columns: site_id, component_id, visitors, conversions,
                 control_visitors, control_conversions

    Returns:
    --------
    PyMC model and trace
    """

    # Extract dimensions
    n_sites = data['site_id'].nunique()
    n_components = data['component_id'].nunique()

    # Calculate observed lift for each test
    data['treatment_cr'] = data['conversions'] / data['visitors']
    data['control_cr'] = data['control_conversions'] / data['control_visitors']
    data['observed_lift'] = (data['treatment_cr'] - data['control_cr']) / data['control_cr']

    # Standard error of lift (delta method approximation)
    data['se_lift'] = np.sqrt(
        (data['treatment_cr'] * (1 - data['treatment_cr'])) / data['visitors'] +
        (data['control_cr'] * (1 - data['control_cr'])) / data['control_visitors']
    ) / data['control_cr']

    # Index variables
    site_idx = data['site_id'].factorize()[0]
    comp_idx = data['component_id'].factorize()[0]

    with pm.Model() as model:
        # === HYPERPRIORS ===
        # Population mean of component effects
        mu_overall = pm.Normal('mu_overall', mu=0.10, sigma=0.05)

        # Variance of component effects
        tau = pm.HalfNormal('tau', sigma=0.10)

        # Variance of site effects
        sigma_site = pm.HalfNormal('sigma_site', sigma=0.05)

        # Variance of interactions
        sigma_interaction = pm.HalfNormal('sigma_interaction', sigma=0.03)

        # === COMPONENT EFFECTS ===
        # True underlying effect for each component
        mu_component = pm.Normal(
            'mu_component',
            mu=mu_overall,
            sigma=tau,
            shape=n_components
        )

        # === SITE EFFECTS ===
        # Site-specific baseline adjustment
        alpha_site = pm.Normal(
            'alpha_site',
            mu=0,
            sigma=sigma_site,
            shape=n_sites
        )

        # === INTERACTION EFFECTS ===
        # Component x Site interaction
        beta_interaction = pm.Normal(
            'beta_interaction',
            mu=0,
            sigma=sigma_interaction,
            shape=(n_sites, n_components)
        )

        # === EXPECTED LIFT ===
        expected_lift = (
            mu_component[comp_idx] +
            alpha_site[site_idx] +
            beta_interaction[site_idx, comp_idx]
        )

        # === LIKELIHOOD ===
        # Observed lift ~ Normal(expected, measurement_error)
        y_obs = pm.Normal(
            'y_obs',
            mu=expected_lift,
            sigma=data['se_lift'].values,
            observed=data['observed_lift'].values
        )

        # === INFERENCE ===
        trace = pm.sample(
            2000,
            tune=1000,
            chains=4,
            return_inferencedata=True,
            target_accept=0.95
        )

    return model, trace


def analyze_results(trace, component_names):
    """
    Extract rankings and recommendations from model results.
    """
    # Get posterior samples for component effects
    mu_samples = trace.posterior['mu_component'].values
    mu_samples = mu_samples.reshape(-1, mu_samples.shape[-1])

    results = []
    for i, name in enumerate(component_names):
        samples = mu_samples[:, i]
        results.append({
            'component': name,
            'mean_effect': np.mean(samples),
            'ci_low': np.percentile(samples, 5),
            'ci_high': np.percentile(samples, 95),
            'prob_positive': np.mean(samples > 0),
            'std': np.std(samples)
        })

    df = pd.DataFrame(results)
    df['score'] = df['prob_positive'] * df['mean_effect']
    df = df.sort_values('score', ascending=False)

    return df


# === USAGE EXAMPLE ===
if __name__ == "__main__":
    # Sample data structure
    data = pd.DataFrame({
        'site_id': ['mv', 'mv', 'sr', 'sr', 'lb', 'lb'],
        'component_id': ['payment', 'guarantee', 'payment', 'guarantee', 'payment', 'guarantee'],
        'visitors': [50000, 50000, 30000, 30000, 20000, 20000],
        'conversions': [1480, 1390, 660, 620, 740, 700],
        'control_visitors': [50000, 50000, 30000, 30000, 20000, 20000],
        'control_conversions': [1250, 1250, 540, 540, 640, 640]
    })

    model, trace = build_hierarchical_model(data)
    results = analyze_results(trace, ['payment', 'guarantee'])
    print(results)

Key Model Insights

What the hierarchical approach tells us that simple averages can't

Shrinkage Effect

Extreme results from small sites get "pulled toward" the overall mean. A +50% lift from a 1,000-visitor site gets appropriately discounted, while the same result from a 100,000-visitor site is trusted more.

Borrowing Strength

Even if Site C only tested 3 components, it benefits from data on all 8 components from Sites A and B. The model "borrows" information across sites to make better estimates everywhere.

Uncertainty Quantification

Instead of "Component 1 lifts 18%", we get "Component 1 has 94% probability of lifting between 12-24%". This enables better decision-making under uncertainty.

When to Use This Model

Good Fit

  • Testing same components across 3+ sites
  • Sites have different baseline conversion rates
  • Some tests have small sample sizes
  • You want to predict performance on new sites
  • Need probability estimates, not just point estimates

Not Ideal

  • Testing only on a single site
  • Components are site-specific (can't be replicated)
  • All sites have identical audiences
  • You need results in real-time (model needs batch data)
  • Sample sizes are very large (simple t-tests suffice)
