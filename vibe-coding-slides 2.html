The Core Skill

The VIBE Framework

A simple structure for defining your requirements

V

Vision

What is this? What does it do? What problem does it solve?

I

Interaction

Who uses it? What actions do they take? What do they see?

B

Backend

What data needs to be stored? Any user accounts? Any external services?

E

Experience

What's the visual style? What's the emotional tone? Any reference examples?

Example Prompt

# VISION I need a landing page for my 5-Day Meditation Challenge. It's a free email course that helps busy entrepreneurs reduce stress through daily 10-minute practices. # INTERACTION Visitors should: - See the value proposition immediately - Take a short 3-question quiz - Enter their email to get started - See a confirmation message after signup # BACKEND I need a database to store: - Email addresses - Quiz answers - Signup timestamp # EXPERIENCE Style: Calm, modern, minimal. Think Headspace meets Apple. Colors: Soft blues, white backgrounds, subtle gradients.

The Process

The Iteration Loop

Vibe coding is conversational. Your first result won't be perfect.

1. Generate

AI builds first version

2. Review

Look at what it created

3. Refine

Tell AI what to change

4. Repeat

Until you're satisfied

Pro Tips

Better Prompts

  • Be specific: "#3B82F6" beats "blue"
  • Give examples: "Like the signup form on Calm.com"
  • One thing at a time: Request one change, see result, then next
  • Describe outcomes: "Users should feel excited" not "Use exciting design"

Core Concept

Understanding Databases

Simple Mental Model

A Database is a
Spreadsheet with Superpowers

Spreadsheet Term Database Term Example
A sheet/tab A table "users", "habits", "entries"
A column A field "email", "name", "created_at"
A row A record One user, one habit entry
VLOOKUP A relationship Connecting user to their entries

Example Database Design

# TABLE: users - id (auto-generated unique ID) - email - name - created_at # TABLE: habits - id - user_id (links to users table) - habit_name - target_frequency - created_at # TABLE: habit_entries - id - habit_id (links to habits table) - completed_date - notes (optional)
