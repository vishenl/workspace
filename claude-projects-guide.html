How to Build a Great Claude Project

A step-by-step guide for turning any body of knowledge into an AI-powered strategic advisor.

What Is a Claude Project?

A Claude Project lets you upload knowledge files and set custom instructions so Claude becomes a persistent expert on your topic. It remembers everything across conversations.

Think of it as giving Claude a "brain" on a specific subject. Instead of re-explaining your business, your frameworks, or your strategy every time you start a new conversation, a Project carries all that context forward. You talk to it like a team member who has read every document and remembers every decision.

The 5-Step Process

Follow these steps in order. Each one builds on the last.

Step 1: Start With Raw Material

Your raw material could be anything:

  • Meeting transcripts and strategy session recordings
  • Strategy documents, playbooks, and SOPs
  • Research papers, reports, or course content
  • Email threads, Slack exports, or interview notes

The messier the better -- Claude excels at extracting structure from chaos. You do not need to clean things up before feeding them in.

Example

"We started with 5 hours of raw strategy session transcripts. No formatting, no structure -- just a wall of text from a Zoom recording. Claude turned it into 14 structured knowledge files in under an hour."

Step 2: Extract and Structure the Knowledge

Use Claude Code or Claude.ai to process your raw material into structured markdown.

  • Have Claude identify the key topics, frameworks, direct quotes, and action items
  • Ask it to organize by theme, not by chronology
  • Do not try to fit everything into one file -- that is the most common mistake people make

Tip

Ask Claude: "Identify the 10-15 distinct topics in this material and suggest a file structure." It will give you a clean breakdown you can use as your starting point.

Step 3: Break Into Granular Files

Structure matters. One topic per file, not one giant document.

  • Use numbered naming: 01-topic-name.md, 02-topic-name.md
  • Each file should be self-contained and useful on its own
  • Create an 00-INDEX.md that maps all files and their contents

Why granular?

Claude retrieves better from focused files. A 50-page document dilutes retrieval -- Claude has to search through everything to find what matters. 15 focused files means precision answers every time.

Here is a real example file structure:

knowledge-base/ 00-INDEX.md -- Master index 01-through-line-model.md -- Core concept 02-right-fit-client.md -- Target persona 03-event-formula.md -- Event structure 04-speaker-playbook.md -- Speaker management 05-sales-engine.md -- Sales & pricing 06-content-strategy.md -- Content approach 07-team-structure.md -- Roles & responsibilities 08-brand-voice.md -- Tone & messaging 09-copy-frameworks.md -- Writing formulas 10-metrics-kpis.md -- What to measure 11-case-studies.md -- Past successes 12-objection-handling.md -- Common pushbacks 13-partnerships.md -- Partner strategy 14-non-negotiables.md -- Protected elements CLAUDE-PROJECT-INSTRUCTIONS.md -- System prompt

Step 4: Write the Custom Instructions

This is the system prompt that tells Claude WHO it is and HOW to behave. It is the single most important piece. Include these six elements:

  1. Identity -- "You are a [role] with deep knowledge of [domain]"
  2. Core Principles -- 5-8 rules Claude should always follow (e.g., "Always bring recommendations back to the right-fit client persona")
  3. File Map -- Quick reference of what is in each knowledge file
  4. Usage Guide -- "Planning a summit? Start with files 03, 04, 01" / "Writing copy? Start with 09, 02, 12"
  5. Voice and Tone -- How Claude should communicate (direct, tactical, reference quotes, etc.)
  6. Key People -- Names and roles so Claude can reference them naturally

Here is a simplified example:

# Events Strategy Advisor -- Claude Project Instructions ## Who You Are You are a senior events strategist with deep expertise in designing transformational live experiences. You have studied every strategy session, playbook, and case study in the knowledge base. ## Core Principles 1. Every recommendation must connect to the Right-Fit Client persona (see file 02) 2. Always reference the Through-Line Model when discussing event flow (see file 01) 3. Use direct quotes from strategy sessions when they exist 4. Be specific and tactical -- no generic advice 5. If you are unsure, say so -- never fabricate frameworks ## Knowledge Files | # | File | Contains | |----|-------------------------|-----------------------------| | 01 | through-line-model.md | Core event philosophy | | 02 | right-fit-client.md | Target audience persona | | 03 | event-formula.md | Event design framework | | 04 | speaker-playbook.md | How to select & brief speakers | | 05 | sales-engine.md | Pricing & sales strategy | ## How to Use - Planning an event? Start with files 03, 04, 01 - Writing sales copy? Start with 05, 02, 09 - Briefing a speaker? Start with 04, 01, 08 ## Voice & Tone Direct, confident, tactical. Reference real quotes and data. Avoid generic business speak. Talk like a senior advisor in a strategy meeting. ## Key People - Sarah (Head of Events) -- primary decision maker - James (Sales Lead) -- owns revenue targets - Priya (Content Director) -- owns messaging

Step 5: Upload and Test

Now bring it all together:

  1. Go to claude.ai and navigate to Projects
  2. Create a New Project
  3. Paste your custom instructions into the Custom Instructions field
  4. Upload all your .md files as Project Knowledge
  5. Test with real questions your team would actually ask
  6. Iterate: if Claude gives weak answers on a topic, that knowledge file needs more detail

Testing tip

Start with the hardest questions first. If Claude can handle "Design a 3-day summit agenda for enterprise clients using our event formula," the easy questions will take care of themselves.

Best Practices

Do

  • Keep files under 200 lines each for best retrieval
  • Use headers, bullet points, and tables -- Claude parses structured text better
  • Include direct quotes from experts and sources -- it adds authenticity to Claude's answers
  • Add a "How to Use" section in your instructions pointing to specific files by use case
  • Version your knowledge base -- add new files as you learn more (15, 16, 17...)
  • Test with the hardest questions first

Don't

  • Put everything in one massive file
  • Write vague instructions ("be helpful") -- be specific about the domain and rules
  • Upload raw, unstructured transcripts as knowledge files -- process them first
  • Forget the index file -- it helps Claude navigate your knowledge base
  • Skip the "Core Principles" -- they are the guardrails that keep Claude on-message

What You Can Build With This

The pattern works for any domain. Here are six examples to get you thinking.

Strategy Advisor

Upload session notes and strategy docs. Get a consultant that remembers every decision, framework, and context from your sessions.

Brand Voice Guide

Upload style guides and writing examples. Get consistent copy across your entire team without endless review cycles.

Product Expert

Upload PRDs, documentation, and user research. Get instant product knowledge for anyone on the team.

Onboarding Buddy

Upload SOPs, processes, and org charts. Give new hires an assistant that can answer questions about how things work.

Course Designer

Upload curriculum frameworks and learning design principles. Get an AI teaching assistant that designs to your standards.

Sales Playbook

Upload objection handling scripts and sales frameworks. Get real-time support for reps during calls and follow-ups.
