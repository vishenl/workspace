#### Day 4: The Language of Building
**Lesson Title:** "How to Talk So AI Understands (Prompt Engineering for Code)"

**Hook:**
*"The difference between 'it doesn't work' and 'this is exactly what I wanted' is how you communicate. Let me show you the framework."*

**Core Content:**
- **The Vibe Coding Prompt Formula:**
  - Context: What kind of app/feature
  - Requirements: Specific functionality needed
  - Constraints: What to avoid or limitations
  - Style: Design preferences and tone

- **Example Breakdown:**

  ❌ Bad: "Make a todo app"

  ✅ Good: "Create a todo list app where I can:
  - Add tasks with a title and optional notes
  - Mark tasks as complete (strike-through style)
  - Delete tasks with a confirmation
  - Tasks should persist when I refresh the page
  - Use a calm, minimalist design with soft colors
  - Mobile-friendly layout"

- **The Iteration Language:**
  - "This works, but can you make [specific change]?"
  - "Keep everything the same, but update [specific element]"
  - "I'm getting this error: [paste error]. What's wrong?"
  - "Show me how this code works" (learning mode)

**Practice Exercise:**
"Prompt Engineering Lab"
- Given 5 vague requests, rewrite them using the Vibe Coding Prompt Formula
- Compare with provided "expert" versions
- Try prompts in Replit and see the difference in quality

**Community Prompt:**

#### Day 5: Reading the Matrix (Understanding Code Basics)
**Lesson Title:** "You Don't Need to Write Code, But You Should Read It"

**Hook:**
*"Imagine trying to edit a document without being able to read. That's vibe coding without basic code literacy. Today, you learn to read the Matrix."*

**Core Content:**
- **The Building Blocks** (10-minute crash course):
  - Variables: Named containers for data (`let name = "Sarah"`)
  - Functions: Reusable blocks of instructions
  - Conditions: If/then logic (`if user is logged in, show dashboard`)
  - Loops: Doing something repeatedly
  - Objects: Organizing related data together

- **You don't need to memorize syntax!**
  - You just need to recognize patterns
  - AI handles the syntax, you handle the logic

- **How to read AI-generated code:**
  - Look for comments (lines starting with //)
  - Identify the main sections (structure, style, behavior)
  - Find where your content is defined
  - Spot where user interactions happen

**Interactive Exercise:**
"Code Detective Challenge"
- Provided with 3 small code snippets

  - "What happens when someone clicks the submit button?"
  - "Where is the user's name displayed?"

**Practice:**

#### Day 6: Debugging Like a Builder
**Lesson Title:** "When Things Break (And How to Fix Them)"

**Hook:**
*"Here's a secret: professional developers' code breaks constantly. The difference is they know how to fix it. Today, you join that club."*

**Core Content:**
- **The Debugging Mindset:**
  - Errors are feedback, not failure
  - Every error message is a clue
  - The fix is usually simpler than you think

- **The Vibe Coding Debug Process:**
  1. **Read the error** (it's usually helpful!)
  2. **Copy/paste to AI:** "I'm getting this error: [error message]. Here's my code: [code]. What's wrong?"
  3. **Test the fix**
  4. **Understand what happened** (ask AI to explain)

- **Common issues and instant fixes:**
  - "Nothing happens when I click" → Check if function is connected to button
  - "Page is blank" → Check browser console for errors
  - "Styles not showing" → Check if CSS file is linked
  - "Changes not appearing" → Hard refresh (Cmd+Shift+R / Ctrl+Shift+R)

**Practice Exercise:**
"Break and Fix Lab"
- Provided with intentionally broken code examples
- Use AI to diagnose and fix each one
- Build confidence that everything is fixable

**Real-World Practice:**
Break something in your landing page intentionally:
1. Delete a closing tag
2. Ask AI to help you fix it
3. Reflect: How did it feel? What did you learn?

**Community Prompt:**
"What broke for you this week? How did you fix it? Let's normalize that building = breaking + fixing!"

  2. **Stick to 2-3 colors** - Choose a palette and stick to it
  3. **Typography hierarchy** - Big for important, small for details

- **User Experience Polish:**

```
I have an existing app that does [current functionality].

I want to add: [new feature description]

REQUIREMENTS:

Here's my current code structure: [paste relevant code or description]

Please:

2. Implement it step by step

4. Maintain consistent styling
```

```
I'm getting this error: [paste error message]

CONTEXT:
- What I was trying to do: [action]
- What happened instead: [unexpected behavior]

HERE'S MY CODE: [paste relevant code]

Please:
1. Explain what's causing this error
2. Provide the fix
3. Explain why the fix works
4. Suggest how to avoid this in the future
```

```
I want to improve the design of [component/page].

CURRENT STATE: [describe or show screenshot]

DESIRED AESTHETIC:

Please:
1. Suggest a cohesive design direction
2. Provide updated code with new styles
3. Ensure mobile responsiveness
4. Add subtle animations if appropriate
```

```
Can you explain how this code works?
```
