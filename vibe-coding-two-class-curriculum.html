Introduction

What is Vibe Coding?

Vibe coding is the practice of building software by describing what you want in natural language, and letting AI write the code for you. Instead of learning programming syntax, you learn to communicate your vision clearly to an AI coding agent.

The Core Shift

Old Way: Learn to code → Write syntax → Debug errors → Months of learning

Vibe Coding: Describe what you want → AI builds it → Iterate with feedback → Hours to results

Understanding the Stack

The Infrastructure Layers

Before we dive into building, let's understand the key components that make apps work. This knowledge helps you communicate better with AI and troubleshoot when needed.

🤖 AI Coding Agent (Lovable, Claude Code, Cursor)
↓
🗃 Database & Authentication (Supabase)
↓
📁 Code Repository (GitHub)
↓
🌐 Hosting & Deployment (Vercel, Netlify)

Understanding Each Layer

Layer 1: AI Coding Agent

What it does: Translates your natural language descriptions into working code.

Examples: Lovable, Claude Code, Cursor, Bolt.new

Your role: Describe what you want clearly. The AI writes the code.

Layer 2: Database & Authentication

What it does: Stores data permanently (user info, submissions, content) and handles user login/signup.

Examples: Supabase (free tier), Firebase, Neon

Your role: Tell the AI what data you need to store. It sets up the database tables.

Layer 3: Code Repository

What it does: Stores your code files, tracks changes, enables collaboration.

Examples: GitHub, GitLab

Your role: Most AI tools handle this automatically. You can view your code history.

Layer 4: Hosting & Deployment

What it does: Makes your app accessible on the internet with a URL.

Examples: Vercel, Netlify, Lovable's built-in hosting

Your role: Click "deploy" or it happens automatically.

  • Database: One-click Supabase integration (free tier included)

This means you can focus on what you want to build, not on connecting different services together.

20-35 min Part 3: The Prompt Framework

The key skill in vibe coding is learning to define your requirements clearly. Use this framework for every project:

The VIBE Framework for Prompts
V
Vision

What is this? What does it do? What problem does it solve?

I
Interaction

Who uses it? What actions do they take? What do they see?

B
Backend

What data needs to be stored? Any user accounts? Any external services?

E
Experience

What's the visual style? What's the emotional tone? Any reference examples?

Example Prompt Using VIBE Framework
# VISION I need a landing page for my 5-Day Meditation Challenge. It's a free email course that helps busy entrepreneurs reduce stress through daily 10-minute practices. # INTERACTION Visitors should: - See the value proposition immediately (headline + benefits) - Take a short 3-question quiz to personalize their experience - Enter their email to get started - See a confirmation message after signup # BACKEND I need a database to store: - Email addresses - Quiz answers (so I can segment my audience) - Signup timestamp # EXPERIENCE Style: Calm, modern, minimal. Think Headspace meets Apple. Colors: Soft blues, white backgrounds, subtle gradients. Feeling: Peaceful but professional.
The Iteration Loop

Vibe coding is conversational. Your first result won't be perfect. That's expected.

  1. Generate: AI builds first version
  2. Review: Look at what it created
  3. Refine: Tell AI what to change ("Make the headline bigger", "Add a testimonial section")
  4. Repeat: Keep iterating until you're satisfied

Pro Tips for Better Prompts

  • Be specific: "Blue" is vague. "#3B82F6 (Tailwind blue-500)" is specific.
  • Give examples: "Like the signup form on Calm.com" works great.
  • One thing at a time: Request one change, see the result, then request the next.
  • Describe outcomes: "Users should feel excited to sign up" not "Use exciting design"

Q&A Session (30 Minutes)

Q: "How is this different from Wix or Squarespace?"

Those are template-based builders where you drag and drop pre-made components. Vibe coding with AI lets you describe custom functionality - like our quiz with database storage. You're not limited to templates. You describe what you want, AI builds custom code for it.

Q: "Is Lovable free?"

Lovable has a free tier that lets you build and deploy projects. For more advanced features and higher usage, there are paid plans. The free tier is enough to learn and build your first several projects. Supabase also has a generous free tier for database storage.

Q: "What if the AI doesn't understand what I want?"

Rephrase your request with more specificity. Give examples. Break it into smaller requests. Say "Show me what you built so far and let me give feedback." The conversation is iterative - you're guiding the AI, not expecting perfection on the first try.

Q: "Can I edit the code later if I need to?"

Yes! The code is yours. It's stored in GitHub automatically. You can hand it off to a developer later, or keep iterating with AI. Nothing is locked away.

Q: "How secure is the database?"

Supabase is a production-grade database used by thousands of companies. It has built-in security, row-level security policies, and is regularly audited. For most use cases, it's more secure than custom solutions because security best practices are built in.

10-25 min Part 2: Understanding Databases & Authentication

Database Concepts Made Simple

Think of a database like a spreadsheet with superpowers:

Spreadsheet Term Database Term Example
A sheet/tab A table "users", "habits", "entries"
A column A field "email", "name", "created_at"
A row A record One user, one habit entry
VLOOKUP A relationship Connecting a user to their entries
Example: Habit Tracker Database Design
# TABLE: users - id (auto-generated unique ID) - email - name - created_at # TABLE: habits - id - user_id (links to users table) - habit_name (e.g., "Meditate", "Exercise") - target_frequency ("daily", "weekly") - created_at # TABLE: habit_entries - id - habit_id (links to habits table) - completed_date - notes (optional)

The relationship: Each user has many habits. Each habit has many entries.

User Authentication Explained

Authentication = verifying who someone is.

  1. Sign Up: User creates account (email + password stored securely)
  2. Log In: User enters credentials, gets a "session" (stays logged in)
  3. Protected Pages: Some pages only visible when logged in
  4. User-Specific Data: Each user only sees their own data

Good News: Supabase Handles This

Supabase has built-in authentication. You just tell Lovable "add user authentication with Supabase" and it sets up signup, login, password reset, and session management automatically. You don't need to understand the security details.

25-35 min Part 3: Understanding API Keys

What Are API Keys?

An API key is like a password that lets your app talk to external services.

Examples of services that need API keys:

  • OpenAI/Claude: To use AI in your app
  • Stripe: To accept payments
  • SendGrid/Resend: To send emails
  • Google Maps: To show maps
  • Weather API: To show weather data
How API Keys Work
1
Get the Key

Sign up for the service (OpenAI, Stripe, etc.) and find your API key in their dashboard.

2
Store It Securely

Add the key to your app's environment variables (Lovable has a place for this).

3
Use It in Your App

Tell Lovable to use the API. Example: "Add a button that sends user input to OpenAI and displays the response."

API Key Security Rules

  • Never share API keys publicly (don't paste in chat, don't commit to public GitHub)
  • Use environment variables (Lovable handles this properly)
  • Set spending limits on paid APIs (OpenAI, etc.) to avoid surprise bills
  • Regenerate if exposed - if you accidentally share a key, create a new one

Q&A Session (30 Minutes)

Q: "How much does the database cost as I get more users?"

Supabase free tier includes 500MB storage and 2GB bandwidth - enough for thousands of users for most apps. Beyond that, their Pro plan is $25/month and handles significant scale. You only upgrade when you have real traction.

Q: "Can I accept payments in my app?"

Yes! You'd integrate Stripe. Get your Stripe API keys, add them to Lovable's environment variables, and prompt: "Add Stripe payment for a $29 monthly subscription. When user pays, update their account status in the database to 'premium'." Lovable can build checkout flows, handle webhooks, and manage subscription status.

Q: "What if I want to add a feature later that AI can't handle?"

The code is standard React/TypeScript stored in GitHub. Any developer can pick it up. Many people start with AI, validate their idea, get traction, then hire developers for complex features. You're not locked in - the code is portable.

Q: "How do I make my app mobile-friendly?"

Lovable builds responsive apps by default. But you can prompt: "Make sure this looks great on mobile devices. Test the layout at different screen sizes. Add mobile-specific navigation." It will generate mobile-optimized CSS.

Q: "Is this good enough for a real business or just prototypes?"

It depends on scale. For launching and validating - absolutely production-ready. For serving millions of users - you might need optimization. But many real businesses run on exactly this stack. Start here, optimize when you need to.
